# 本轮范围说明

## 一、总原则

- 课题名称保持为“校园生活平台”。
- 本轮不追求覆盖平台全部模块，而是围绕数据库设计最有代表性的子系统做深化。
- 所有改进优先体现数据库课程目标：业务建模、关系设计、约束实现、事务一致性、权限与审计。

## 二、纳入本轮主线的模块

### 1. 平台基础子系统

- 身份与鉴权边界：`auth.users` 与 `public.profiles`
- 组织结构：部门树、闭包表、用户-部门、岗位
- RBAC：角色、权限、用户-角色、角色-权限
- 数据范围：角色数据范围、范围部门映射
- 审计日志：append-only 审计记录

### 2. 功能房预约

- 楼房、房间、预约、参与人、封禁
- 时间冲突、状态流转、并发一致性、排行榜统计

### 3. 课程资源分享

- 专业、课程、资源、专业负责人
- 审核流、去重约束、下载事件、积分事件

### 4. 数字图书馆（可选扩展）

- 与课程资源分享模型相近，可作为“同构业务扩展”补充
- 仅在主线模块完成后继续深化

## 三、明确不作为本轮重点的内容

- 通知公告
- 问卷
- 投票
- 失物招领
- 材料收集
- Workbench / AI 相关历史能力
- 前端视觉打磨与复杂交互细节

## 四、本轮优先改进方向

1. 强化数据库层约束，而不是只在服务层校验业务规则。
2. 让平台基础子系统形成一套可答辩的数据库主线，而不只是工程基础设施。
3. 给课程资源和功能房预约补齐更适合课程设计表达的报告材料。
4. 保持项目仍可运行，但文档、目录和后续改进优先服务数据库课程设计。
