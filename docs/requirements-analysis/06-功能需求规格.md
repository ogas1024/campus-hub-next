# 06 功能需求规格

## 6.1 编写说明

本章采用标准化需求规格的写法，对系统应具备的主要功能进行描述。每条需求均尽量明确以下内容：

- 功能目标
- 适用角色
- 触发条件
- 业务结果
- 优先级

这些需求编号将作为后续数据库设计、接口设计、测试用例设计和答辩说明的重要依据。

## 6.6 需求特点总结

从功能需求规格可以看出，本课题具有以下特点：

- 不是单纯的 CRUD 系统
- 存在明显的多角色协作
- 存在多个需要明确生命周期的状态对象
- 存在多对多关系、层级关系和事件型数据
- 需要对权限、数据范围、审核、统计和审计进行统一考虑

这些特点决定了后续数据库设计不能仅满足“能存数据”，而应进一步考虑：

- 主键与外键设计
- 业务状态与辅助字段一致性
- 多对多关系拆分
- 事件表与主体表分层
- 查询和统计的索引支撑
