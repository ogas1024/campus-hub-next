# 正式报告正文说明

## 1. 定位

本目录用于后续组装“最终提交版”的课程设计报告正文。

它和 `docs/report/` 里的其他文档区别在于：

- 其他文档更像支撑材料、专题说明、写作素材
- 本目录中的内容应是最后真正要交的章节化成稿

## 2. 正文应包含什么

正式报告正文建议至少覆盖以下章节：

1. 课题概述与建设目标
2. 需求分析
3. 概念结构设计
4. 逻辑结构设计
   - 关系模式、主键、外键、候选键、函数依赖、范式判断
5. 物理设计与实现
   - 索引设计依据、删除策略、检查约束、触发器 / 数据库函数
6. 典型业务数据库实现
7. 典型 SQL 与事务设计
8. 系统测试与结果分析
   - 约束失败样例、并发一致性、已落库 / 未完全落库规则边界
9. 总结与展望

## 3. 与现有文档的关系

正文不是从零写，而是对现有材料进行“收束和合并”：

- 需求分析主要来自 `requirements-analysis/`
- 数据库设计说明主要来自 `docs/report/overview/`
- 模块分析主要来自 `docs/report/modules/`
- 物理设计、事务、测试主要来自 `docs/report/database/`

## 4. 当前状态

本目录已经创建一份可继续打磨的合并版正文初稿：

- `校园生活平台数据库课程设计报告.md`

这份初稿已经主动收束以下课程设计重点：

- 概念结构设计 -> 逻辑结构设计 -> 物理设计 -> 测试验证主线
- 候选键 / 主属性 / 非主属性 / 函数依赖
- 3NF / BCNF 与必要冗余解释
- 显式外键、`CHECK`、`UNIQUE`、触发器、事务与并发控制
- 已落库规则与真实剩余边界

## 5. 后续建议

后续若要进一步提交定稿，可在当前合并版基础上继续二选一：

1. 继续保留单文件成稿，直接做排版、精简和截图补充。
2. 拆成章节文件，例如：
   - `01-课题概述与需求分析.md`
   - `02-概念结构设计.md`
   - `03-逻辑结构设计.md`
   - `04-物理设计与实现.md`
   - `05-系统测试与结果分析.md`
   - `06-总结与展望.md`

在没有明确拆分需要前，当前推荐继续维护单文件版本，避免事实口径再次分散。
